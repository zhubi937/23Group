# 截图成事 · W07 整合工程

基于多源信息整合的鸿蒙个人事务管理应用。此包为 **15 周计划中第 7 周里程碑的累计源码**，版本 `0.7.2`。后续第 8–15 周在此工程上逐步增加功能，每周交付新的完整工程 ZIP，并更新本 README 的版本、增量和验证记录。

界面采用米白、朱红配色。应用无需注册，不接入云端 AI，不声明网络访问权限。图片副本、OCR 片段、用户确认值、关联来源和历史记录保存在应用沙箱内。

## 0. 0.7.2：系统 OCR 不可用时自动离线转写

此版解决 0.7.1 只显示“不支持系统文字识别”，真实截图仍无法自动转写的问题。系统 OCR 可用时优先使用系统；能力缺失、初始化失败或结果为空时，自动使用随包的 **Tesseract 5.5.0 + 中英文离线模型**，在手机/模拟器进程内运行，不上传图片、无需 API Key、无需电脑识别服务器。

### 已用真实截图验证

在当前 Mate 90 Pro x86_64 模拟器中，通过系统图库选择用户提供的课程作业截图，实际离线识别出 **17 段原文**。没有为该图片预置转写文字或坐标，识别结果来自本机 C++ 引擎。

- 标题：`《移动应用开发》项目开题提交材料`。
- 截止时间：`2026-11-15 23:59`。
- 备注：PPT、开题报告、代码仓地址/进度截图、小组提交等要求。
- 点击“截止时间”，原图中的日期和时间显示对应红框。红框来自真实的词级 OCR 坐标。
- 作业页面的开放区间不再误填为日程的开始和结束时间。
- OCR 将“截止”读成“裁止”时，保留真实转写文字，并提示疑似错字、提供候选截止时间，由用户核对。

源码支持构建 `x86_64` 和 `arm64-v8a`；当前只在现有 x86_64 模拟器完成真实识别验收，arm64 真机尚待复核。系统 OCR 自身仍检测为不支持；实际转写通过本机离线引擎完成。系统提醒仍存在之前记录的设备服务错误，未在本次修复中解决。

### 使用方法

1. 打开“截图成事”，导入图库中的图片；识别成功后会显示“本机离线识别”和原文。
2. 老版本导入失败的来源可重新打开，点击“识别图片（系统 / 本机离线）”；同一图片再次导入会复用来源，必要时重新识别。
3. 原文框可修正错字；按文字重新整理后明确标记为“手工补充”，不会伪造图像坐标。也可只修改下方个别字段，保留原始识别依据。
4. 点击有依据的字段名或“定位原文”，展开原图并显示红框；检查截止时间和提交要求后再确认保存。

0.7.1 的中文预编辑保护、键盘避让、原图收起/展开均保留。屏幕键盘已实测能选词输入“你好”“成都东”并保存恢复。电脑实体键盘到模拟器的输入法通道尚未完成直接打字实测；可在电脑上输入中文后复制，再在模拟器输入框尝试粘贴。当前 DevEco 版本支持主机与模拟器互相复制粘贴，具体快捷键/键盘组合仍以当前运行环境为准。

本修复属于 W07 里程碑，仍保留旧版源码包，不充当 W08 的新增工作。生产应用及旧的独立输入测试应用保留各自数据，项目 ZIP 使用正式应用标识 `com.jietuchengshi.app`。

## 1. 快速运行

### 在 DevEco Studio 中运行

1. 解压整个项目文件夹。选择 **Open**，打开包含 `build-profile.json5` 和 `hvigorfile.ts` 的根目录。
2. 使用已安装的 **DevEco Studio 26.0.0.821 / HarmonyOS 26.0.0 SDK**，等待工程同步。工程包含本机 OCR 的完整 C++ 源码和中英文模型，无需填写 API Key 或校园账号。首次原生编译需等待数分钟，后续构建会复用本地缓存。
3. 在设备列表中启动 **Mate 90 Pro** 模拟器，选择 `entry` 模块运行。
4. 首次进入为空列表；可使用“导入截图”“新建”，或在“来源”页打开自制样例。
5. 若 IDE 提示配置签名，在 **Project Structure → Signing Configs** 中按当前开发者环境配置调试签名。源码不携带个人签名、证书、设备 UDID 或开发者账号。本次已有模拟器可直接安装未签名调试 HAP；真机一般需要有效调试签名。

不要只打开 `entry` 子目录，不要将 SDK 目录或其他项目的 `oh_modules` 复制进来。

### 在 Windows PowerShell 中构建

```powershell
# 推荐使用本机安装目录；也可省略参数，由脚本查找已安装的 DevEco Studio。
.\scripts\build.ps1 -DevEcoHome 'C:\path\to\DevEco Studio'
```

脚本只为当前进程配置 Node、Java、SDK，安装工程内的本地类型依赖，并生成本机专用 `local.properties`，不修改系统环境变量。DevEco 自带 CMake/Ninja 会从随包 C++ 源码构建两个 ABI 的离线 OCR 模块；无需额外安装 Tesseract 或在手机上下载模型。构建产物位于：

```text
entry/build/default/outputs/default/entry-default-unsigned.hap
```

ZIP 只交付源码、资源和说明，不附带构建缓存、编译后的应用、个人证书及本地数据库。IDE 生成的 `local.properties`、`.hvigor`、`.cxx`、`oh_modules` 等也不应进入后续每周源码包。

## 2. 第 7 周包含什么

| 功能 | 当前实现 |
|---|---|
| 图片导入 | 系统图片选择器单张选择、预览、保存应用内副本；取消选择不创建事项 |
| 输入保护 | 拒绝空文件、超过 20 MB 或超过 4000 万像素的输入 |
| 截图查重 | 对完整文件内容分块计算 SHA-256；同字节图片复用原来源，清理重复临时副本；不宣称具备感知相似图片去重 |
| OCR 接入 | 系统 OCR 优先；不可用或失败时自动回落随包本机引擎。离线输入最长边最多 2600 像素，文字行/词坐标映射回原图，识别在原生异步线程运行 |
| 字段提取 | 标题、类型、日期、开始/结束、截止、地点、到达站、备注及显式取消状态候选；课程提交页优先正文标题、保留提交要求并区分开放区间 |
| 时间语义 | 区分举行时间与截止时间；出行识别两组时间；有历时时检查是否一致；缺年保留 `MM-DD` 并提醒补全 |
| 原文核对 | 点击字段“定位原文”或字段名，回到原图并显示相应红框；手工新增字段不伪造位置依据 |
| 中文输入 | 原文和各事项字段支持系统中文拼音选词，组合期间保留预编辑；键盘弹出时内容区域自动缩小 |
| 手工补充 | OCR 不支持或失败时可输入原文、按文字整理字段，也可逐项填写；手工文字明确标注无图像坐标 |
| 事项管理 | 新建、编辑、完成、取消、删除；搜索标题/日期/类型/地点/备注，按状态筛选 |
| 基础关联 | 根据标题、类型、日期、地点召回已有事项；用户选择关联、勾选字段并确认前后值后才更新；可始终选择新建 |
| 变更历史 | 保存字段更新前后值、来源关联和时间；删除事项为软删除，保留来源及历史，后续阶段再扩展撤销/回收站 |
| 原子保存 | 当前事项、此次来源及历史在同一数据库事务中写入；历史带当次来源快照；版本校验阻止陈旧编辑覆盖 |
| 提醒接入 | 通知授权、指定日期提醒、一分钟倒计时测试、取消提醒；系统返回成功后才记录提醒 ID；数据库写入失败时补偿取消刚发布的提醒 |
| 数据清理 | 未引用来源可删除；已被事项/历史引用的来源受保护；设置中可确认清空全部本应用数据和已记录提醒 |

提醒不会在标题或日期提取后自动创建。编辑已有提醒的事项之前，应先取消原提醒，避免旧时间继续触发。普通事项允许保留未知年份；设置实际提醒必须有完整日期。

当前提取是可解释的规则基线，不能保证任意布局、复杂聊天上下文、跨页长图和全部自然语言都自动解析正确；用户核对是完整流程的一部分。不以规则测试通过声称达到 PPT 中后期测试集的准确率目标。

## 3. 建议演示顺序

### 出行与红框定位

1. 进入“来源”，点击“出行截图”。它是程序自制的演示图，**文字与坐标是预置的，非真实 OCR 结果**。
2. 找到“开始时间”，点击“定位原文”，原图 `10:56` 对应区域显示红框。地点也可定位到“成都东”。
3. 日期保留 `09-10`；如需要完整日期，可人工填写 `2027-09-10`，不由程序默认为某年。
4. 确认保存，在详情检查两个站点、时间、来源与历史。

### 作业延期与来源保留

1. 在“来源”中打开“作业通知”并保存，截止时间为 `2026-12-18 23:59`。
2. 返回“来源”，打开“延期通知”。在“可能是同一件事”中选择原作业。
3. 按需要勾选采用的字段。若只需要延期，取消标题勾选，只保留截止时间；状态和类型也由独立勾选控制。
4. 点击“确认关联并更新”，查看弹窗中的前后值，再确认。
5. 在详情检查新的 `2026-12-20 23:59`、两份来源及旧截止时间的历史。再次查看旧来源不会自动覆盖个人安排。

### 真实截图与手工补充

1. 点击“导入截图”，在系统选择器中选择一张图并完成选择。
2. 系统服务不可用时会自动进行本机离线识别。检查自动转写、提取项与原文红框；两条识别路径都未完成时保留图片及旧文字，并提示重试或补充。
3. 在手工文字框粘贴原文，例如：

```text
学术讲座通知
举行时间：2026年12月1日 19:00
地点：某报告厅
报名截止：2026年11月30日 18:00
```

4. 点击“按补充文字整理字段”，检查举行时间与截止时间分别提取。该路径不提供 OCR 坐标，界面会明确提示。

### 系统提醒

在待办事项详情设置完整日期和时间，或点击“一分钟测试提醒”，允许系统通知。只有系统接受后才显示已设置。当前模拟器实测拒绝提醒时，事项仍保存，界面不会假报已设置。更换设备后需分别检查发布、应用切后台、实际送达与取消。

### 数据表达

- `SourceRecord`：图片副本路径、哈希、尺寸、导入时间、识别方式、原文片段、候选字段及错误信息。
- `FieldCandidate`：字段值、对应原文、原文片段 ID、原图坐标框和需核对的说明。无坐标时框集合为空。
- `TaskRecord`：用户确认值、来源 ID 集合、状态、版本、提醒信息。来源内容与个人确认值分别保存。
- `HistoryRecord`：动作、时间、前后事项快照、逐字段差异、此次来源 ID 与来源快照。
- SQLite/RDB 中使用 `tasks`、`sources`、`history` 三张表，SQL 采用参数绑定。图片文件在沙箱 `files/sources/` 中。

数据库事务覆盖数据表更新，不宣称能和操作系统提醒服务实现跨系统事务。提醒发布后的数据库失败会尝试取消新提醒；系统进程故障、取消失败等边界仍需真机及故障场景复核。
